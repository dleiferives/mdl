#+title: Minecraft Datapack Language

MDL is a typed compiler for Minecraft Java Edition datapacks, implemented in Rust.
It currently compiles a bounded single-file scalar language through resolved typed
HIR, verified Core SSA, Core optimization, structured Minecraft lowering, target
cost analysis, and deterministic datapack emission. Generated packs are tested on
the official vanilla Java 26.2 dedicated server; no client is required.

* Quick start

Create =example.mdl=:

#+begin_src text
fn choose(flag: Bool, left: Int32, right: Int32) -> Int32 {
    var selected: Int32;
    if (flag) {
        selected = left;
    } else {
        selected = right;
    }
    return selected;
}
#+end_src

Compile it with every CLI-exposed choice explicit:

#+begin_src sh
cargo run -p mdl -- compile example.mdl \
  --output build/example-pack \
  --core-opt baseline \
  --minecraft-opt baseline \
  --namespace example \
  --register-objective mdl.example \
  --description "MDL example"
#+end_src

The CLI refuses to overwrite a nonempty output directory. On success it prints each
source function's generated entry resource and ordered typed scoreboard ABI homes.

* Current source language

The first complete language slice includes:

- =Bool=, =Int32=, and =Void= function results (an omitted result annotation means
  =Void=);
- explicit positional parameter types and optional result annotations;
- immutable =const= and mutable =var= locals;
- forward calls and recursion at the frontend level;
- =if=, =else if=, =else=, assignment, and =return=;
- Boolean negation and typed equality/ordered comparisons; and
- exact source diagnostics, definite assignment, and return-completeness checking.

Arguments evaluate left to right. Types match exactly; there are no implicit
conversions. The current Minecraft backend deliberately rejects recursive call
graphs with a typed lowering error. Arithmetic, strings, lists, structs, loops,
Minecraft context/entity APIs, raw commands, scheduling, and macros are not yet
source features.

The reviewed next contracts keep logical module identity separate from filenames
and route typed Minecraft effects through Core before structured target lowering.
See [[file:notes/compiler/stage-6-modules-plan.md][the module plan]] and
[[file:notes/compiler/stage-6-effects-plan.md][the typed-effect plan]].

* Verification

Fast checks do not launch Java:

#+begin_src sh
cargo test --workspace
#+end_src

The source compiler's four-policy differential runs all combinations of Core
=none|baseline= and Minecraft =none|baseline= in one official-server startup:

#+begin_src sh
MDL_SERVER_JAR=/path/to/minecraft-server-26.2.jar \
MDL_JAVA=/path/to/java25 \
cargo test -p mdl-test --test source_compilation \
  source_compilation_runs_all_four_policies_on_vanilla_26_2 \
  -- --ignored --exact --nocapture
#+end_src

The CLI process-boundary proof compiles through the actual =mdl= binary, installs
the materialized directory in the server harness, and invokes the printed ABI:

#+begin_src sh
MDL_SERVER_JAR=/path/to/minecraft-server-26.2.jar \
MDL_JAVA=/path/to/java25 \
cargo test -p mdl --test server \
  cli_materialized_pack_runs_on_vanilla_26_2 \
  -- --ignored --exact --nocapture
#+end_src
